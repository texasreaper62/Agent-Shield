# Migration Guide: v6.0 to v7.x

This guide covers upgrading Agent Shield from v6.0 (Compliance & Standards) to v7.0, v7.1, and v7.2. Each version is backward-compatible, but several APIs have been superseded by unified replacements that are simpler and more secure.

## Quick Start

The fastest path from v6 to v7.2:

```bash
npm install agentshield-sdk@latest
```

```js
const {
  // v7.0 - Unified MCP security (replaces manual MCPBridge + ConfusedDeputyGuard)
  MCPSecurityRuntime,

  // v7.0 - MCP SDK drop-in protection
  shieldMCPServer,

  // v7.1 - Adaptive detection
  AdaptiveDetector,

  // v7.2 - Indirect prompt injection detection
  IPIADetector,
  createIPIAScanner,
  ipiaMiddleware,
} = require('agentshield-sdk');
```

Replace your manual MCP setup with the unified runtime:

```js
// One-line MCP server protection
const runtime = new MCPSecurityRuntime({
  signingKey: process.env.SHIELD_KEY,
});

// Or wrap an MCP SDK server directly
const server = shieldMCPServer(mcpServer, {
  signingKey: process.env.SHIELD_KEY,
  enforceAuth: true,
});
```

Add IPIA scanning to your RAG pipeline:

```js
const scanRAG = createIPIAScanner({ threshold: 0.4 });
const chunks = await vectorDB.search(query);
for (const chunk of chunks) {
  const result = scanRAG(chunk.text, query);
  if (result.isInjection) chunks.splice(chunks.indexOf(chunk), 1);
}
```

That covers the most important changes. Read on for the full details.

## Breaking Changes

### 1. AES-256-GCM replaces XOR cipher in MCP runtime (v7.0)

The `MCPSecurityRuntime` uses AES-256-GCM for session token encryption and auth context signing. If you were relying on the older XOR-based cipher from the v6 MCP Bridge internals, tokens generated by v6 are not compatible with v7.

**Action required:** Rotate all signing keys when upgrading. Existing sessions will need to re-authenticate.

```js
// v7.0 - signingKey is now used for AES-256-GCM + HMAC
const runtime = new MCPSecurityRuntime({
  signingKey: process.env.SHIELD_KEY, // Use a strong 256-bit key
});
```

### 2. MCPSecurityRuntime is the recommended MCP entry point (v7.0)

The v6 pattern of manually composing `MCPBridge`, `MCPSessionGuard`, `MCPToolPolicy`, and `ConfusedDeputyGuard` still works but is no longer the recommended approach. `MCPSecurityRuntime` unifies all four into a single class with integrated session state machine, behavioral monitoring, and adaptive defense.

**Before (v6):**

```js
const { MCPBridge, MCPSessionGuard, MCPToolPolicy } = require('agentshield-sdk');
const { ConfusedDeputyGuard } = require('agentshield-sdk');

const bridge = new MCPBridge({
  allowedTools: ['search', 'read_file'],
  scanInputs: true,
  scanOutputs: true,
});

const sessionGuard = new MCPSessionGuard();
const toolPolicy = new MCPToolPolicy([
  { tool: 'read_file', scopes: ['fs:read'], roles: ['analyst'] },
]);
const deputyGuard = new ConfusedDeputyGuard({
  enforceContext: true,
  signingKey: process.env.SHIELD_KEY,
});

// Manual wiring for every tool call
const scanResult = bridge.scanToolCall('read_file', args);
const authResult = deputyGuard.validateContext(authCtx);
const policyResult = toolPolicy.check('read_file', userRoles);
```

**After (v7.0):**

```js
const { MCPSecurityRuntime } = require('agentshield-sdk');

const runtime = new MCPSecurityRuntime({
  signingKey: process.env.SHIELD_KEY,
  enforceAuth: true,
  enableBehaviorMonitoring: true,
  allowedTools: ['search', 'read_file'],
  policies: [
    { tool: 'read_file', scopes: ['fs:read'], roles: ['analyst'] },
  ],
  onThreat: (event) => console.log('Threat:', event),
});

// Single call handles scanning, auth, policy, and audit
const session = runtime.createSession({
  userId: 'user-123',
  agentId: 'agent-456',
  roles: ['analyst'],
  scopes: ['fs:read'],
});
const result = runtime.secureToolCall(session.sessionId, 'read_file', args);
```

## New Features

### v7.0 - MCP Security Runtime

#### MCPSecurityRuntime

Unified security layer combining authorization, threat scanning, behavioral monitoring, session state machine, and audit logging. Replaces manual composition of multiple v6 components.

```js
const { MCPSecurityRuntime } = require('agentshield-sdk');

const runtime = new MCPSecurityRuntime({
  signingKey: process.env.SHIELD_KEY,
  enforceAuth: true,
  enableBehaviorMonitoring: true,
  enableStateMachine: true,
  maxSessionsPerUser: 10,
  sessionTtlMs: 3600000,
  maxToolCallsPerSession: 100,
  onThreat: (event) => alertSecurityTeam(event),
  onAudit: (entry) => auditStream.write(entry),
});
```

Key capabilities beyond v6:
- **Session state machine** prevents tool call ordering attacks (e.g., skip_auth, execute, destroy_logs)
- **Per-session token budgets** and tool call limits
- **Integrated LearningLoop** that auto-generates detection patterns from blocked attacks
- **Built-in ContractRegistry and ComplianceAttestor** for runtime governance

#### Adaptive Defense (LearningLoop, ContractRegistry, ComplianceAttestor)

Three interconnected systems from `adaptive-defense.js`:

```js
const {
  LearningLoop,
  AgentContract,
  ContractRegistry,
  ComplianceAttestor,
} = require('agentshield-sdk');

// Self-improving detection: blocked attacks generate new patterns
const loop = new LearningLoop({
  minHitsToPromote: 3,
  promotionConfidence: 0.75,
  onPatternLearned: (pattern) => console.log('New pattern:', pattern),
});
loop.ingest({ text: blockedText, category: 'prompt_injection', confidence: 0.95 });

// Agent contracts: declarative behavioral boundaries
const contract = new AgentContract({
  agentId: 'data-analyst',
  allowedTools: ['search', 'read_file'],
  deniedTools: ['exec', 'shell'],
  maxToolCallsPerMinute: 30,
  maxDelegationDepth: 2,
  allowedScopes: ['db:read', 'fs:read'],
});
const check = contract.verify({
  type: 'tool_call',
  toolName: 'exec',
});
// check.allowed === false, check.violations lists the rules broken

// Compliance attestation: continuous proof of NIST/OWASP/EU AI Act compliance
const attestor = new ComplianceAttestor({
  frameworks: ['nist-ai-rmf', 'owasp-llm-2025', 'eu-ai-act'],
  driftThreshold: 0.9,
  onComplianceDrift: (drift) => alertComplianceTeam(drift),
});
```

#### MCP SDK Integration

Drop-in protection for `@modelcontextprotocol/sdk` servers:

```js
const { Server } = require('@modelcontextprotocol/sdk/server/index.js');
const { shieldMCPServer } = require('agentshield-sdk');

const server = shieldMCPServer(new Server({ name: 'my-server', version: '1.0' }), {
  signingKey: process.env.SHIELD_KEY,
  enforceAuth: true,
  scanInputs: true,
  scanOutputs: true,
  blockOnThreat: true,
  sensitivity: 'high',
  tools: {
    'database_query': { scopes: ['db:read'], roles: ['analyst'] },
    'file_delete': { scopes: ['fs:write'], roles: ['admin'], requiresHumanApproval: true },
  },
  onThreat: (event) => alertSecurityTeam(event),
});
```

For non-SDK MCP servers (plain JSON-RPC 2.0), use `createMCPSecurityLayer()`:

```js
const { createMCPSecurityLayer } = require('agentshield-sdk');

const layer = createMCPSecurityLayer({
  signingKey: process.env.SHIELD_KEY,
  enforceAuth: true,
  sensitivity: 'high',
});

// Wrap your JSON-RPC handler
const inputCheck = layer.processRequest(request, { sessionId });
if (!inputCheck.allowed) return errorResponse(inputCheck.threats);

const response = await handleRequest(request);

const outputCheck = layer.processResponse(response);
if (!outputCheck.safe) logThreats(outputCheck.threats);
```

### v7.1 - Adaptive Detection and CTF

#### AdaptiveDetector

Learns from false positives and false negatives to improve accuracy over time. Persists state to a local JSON file.

```js
const { AdaptiveDetector } = require('agentshield-sdk');

const detector = new AdaptiveDetector({
  storePath: '.agent-shield/adaptive.json',
  similarityThreshold: 0.65,
});

// Record mistakes so similar inputs are handled correctly next time
detector.recordFalsePositive('normal business text that was flagged', 'prompt_injection');
detector.recordFalseNegative('sneaky attack that was missed', 'data_exfiltration');
```

#### SemanticAnalysisHook and CommunityPatterns

```js
const { SemanticAnalysisHook, CommunityPatterns } = require('agentshield-sdk');

// Pluggable LLM-based post-processing classifier
const hook = new SemanticAnalysisHook();

// Load community-contributed detection patterns from local JSON
const community = new CommunityPatterns();
```

#### CTF Challenge System

Security testing through capture-the-flag challenges:

```js
const { CTFEngine } = require('agentshield-sdk');

const engine = new CTFEngine({ difficulty: 'medium' });
const challenges = engine.getChallenges();
const result = engine.submitAttempt('easy_01', 'some sneaky payload');
// result.solved === true/false
```

#### OpenClaw Integration

Register Agent Shield as an OpenClaw skill:

```js
const { OpenClawShieldSkill, shieldOpenClawMessages } = require('agentshield-sdk');

// As a skill
const skill = new OpenClawShieldSkill({ blockOnThreat: true });
openclaw.registerSkill(skill);

// As a message hook
const hook = shieldOpenClawMessages({ blockOnThreat: true });
session.onMessage(hook.scan);
```

#### Agent Contracts (BehaviorContract)

Declarative contracts that enforce what an agent is allowed to do at runtime. See the `AgentContract` example in the v7.0 section above. Contracts are verified continuously, not just at deploy time. Violations are caught instantly and logged.

### v7.2 - Indirect Prompt Injection Detection (IPIA)

Detects indirect prompt injection attacks in RAG pipelines and any scenario where external content is mixed with user intent.

The pipeline: Context Construction, TF-IDF Embedding, Decision Tree Classification, Response.

#### IPIADetector

Full-featured detector with pluggable embedding backends:

```js
const { IPIADetector } = require('agentshield-sdk');

const detector = new IPIADetector({
  threshold: 0.5,     // Detection threshold (0-1)
  action: 'block',    // 'block', 'flag', or 'log'
});

const result = detector.scan(
  'External document content that may contain injections...',
  'User query: summarize this document'
);

if (result.isInjection) {
  console.log('IPIA detected:', result.confidence, result.severity);
}
```

#### createIPIAScanner - RAG pipeline helper

```js
const { createIPIAScanner } = require('agentshield-sdk');

const scanRAG = createIPIAScanner({ threshold: 0.4 });
const chunks = await vectorDB.search(query);
for (const chunk of chunks) {
  const result = scanRAG(chunk.text, query);
  if (result.isInjection) {
    chunks.splice(chunks.indexOf(chunk), 1);
  }
}
```

#### ipiaMiddleware - Express middleware

```js
const { ipiaMiddleware } = require('agentshield-sdk');
const express = require('express');

const app = express();
app.use(express.json());

// Scans req.body.content against req.body.intent
app.post('/api/chat', ipiaMiddleware({
  contentField: 'content',
  intentField: 'intent',
  action: 'block',       // Returns 403 on detection
  threshold: 0.5,
}), (req, res) => {
  // Only reached if no injection detected
  res.json({ reply: processChat(req.body) });
});
```

#### Pipeline components for advanced use

```js
const {
```

## Deprecations

| Deprecated pattern | Replacement | Removed? |
|---|---|---|
| Manual `MCPBridge` + `MCPSessionGuard` + `MCPToolPolicy` + `ConfusedDeputyGuard` composition | `MCPSecurityRuntime` | No, still works. Will be removed in v8.0. |
| XOR cipher for MCP session tokens | AES-256-GCM (automatic in `MCPSecurityRuntime`) | Yes, XOR cipher removed in v7.0. |

All v6 exports (`MCPBridge`, `MCPSessionGuard`, `MCPToolPolicy`, `ConfusedDeputyGuard`, `OWASPv2025Coverage`, `NISTMapper`, `EUAIActClassifier`, etc.) remain available and functional. The v6 compliance modules are unchanged and fully compatible with v7.
